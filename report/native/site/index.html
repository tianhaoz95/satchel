Phones and watches that sign your approvals in hardware

Native apps for iPhone, Apple Watch, Android and Wear OS. Each device holds its own P-256 key in the Secure Enclave or Android Keystore. Once a phone is paired, your node accepts a high-risk approval (revealing a value, moving files, changing VAULT.md) only if that device signed it after Face ID or a fingerprint.

Stack decision: fully native. SwiftUI shares the SatchelKit package across iPhone, Watch and the share extension; Jetpack Compose shares :core across phone and Wear OS. Flutter and React Native can't build watchOS apps, and every security feature here is a platform API.

Why scan to pair, and not just "Sign in with GitHub"?

GitHub proves who you are to the hosted portal. Pairing proves that this phone belongs to this node. The portal is deliberately not allowed to vouch for that.

GitHub / portal can't enroll

If a GitHub login could add a phone, anyone who took over your GitHub account (or the hosted service) could add their own "phone" and approve reveals of your passport number. Two factors would collapse into one.

The QR code carries

Your node's address, a one-time code issued from your signed-in admin page, and the pin of the node's own TLS key. The phone trusts that pin, not a certificate authority or the relay.

The phone proves

It creates its key in secure hardware and signs the pairing message, so the node learns a key the phone provably holds. Self-hosters with no account pair the same way.

Possible later: "Find my node with GitHub" fills in the address, but a short code shown on your admin page still finalizes pairing, so the node, not GitHub, decides.

What you'll need to ship

Apple

  • Apple Developer Program membership; a team ID set as DEVELOPMENT_TEAM in apps/apple/project.yml
  • App IDs dev.satchel.ios (+ .share, .watchkitapp, .watchkitapp.widgets), app group group.dev.satchel, keychain group dev.satchel.shared, Push Notifications capability
  • An APNs auth key (.p8) for the push gateway
  • A demo node and pairing instructions for App Review

Google

  • Play Console account; app id dev.satchel.android for both phone and Wear (the Data Layer requires a matching id and signing key)
  • A Firebase project: put the app id, API key, project id and sender id in Gradle properties satchel.firebase.*, and give the service-account JSON to the push gateway

Push gateway (Cloudflare Worker)

  • wrangler deploy from apps/push-gateway on push.<domain>
  • Secrets: TICKET_KEY (32 random bytes, base64), APNS_KEY_ID, APNS_TEAM_ID, APNS_PRIVATE_KEY, FCM_SERVICE_ACCOUNT
  • Check that Workers can reach APNs over HTTP/2 in your account; if not, move the gateway to the relay VPS (same code, Node runtime)
